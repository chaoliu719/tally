## Context

见 `proposal.md` — Why。这份 change 是补记:skill 已在 `4f12498` 落地,`plugin/skills/export/SKILL.md` 是唯一的事实来源。设计文档要解释的是"为什么 skill 里是这几条规则",因为其中几条并非直觉选择,而是从目标网页的前端脚本(`app.6dc585f9.js`,2026-10 读取)反推出来的。

约束:

- 目标网页(共享记账,`member.gongxiangjizhang.com`)没有 API,只有前端导入页,规则只能靠读它的打包脚本得到;网页改版即可能失效。
- 导出侧不引入新的 MCP 工具。现有读类工具(`search_transactions` / `list_categories` / `list_sources` / `open_transaction_timeline`)已足够,导出逻辑全部落在 skill 与 Agent 侧的脚本里。
- 映射规则依赖账本里的分类层级与 `comment` 原文,这两点都由既有数据模型保证。

## Goals / Non-Goals

**Goals:**

- 用一份短期有效的映射,把 tally 的交易变成目标网页"导入成功且金额正确"的 CSV。
- 把"日期为什么要减一天""为什么没有子分类列"这类反直觉结论固定下来,后人不必重新读一遍压缩脚本。
- 交付前有可执行的对账口径,避免静默少行或金额偏差。

**Non-Goals:**

- 不做通用 CSV 导出器,也不做 CSV 模板系统。当前只有一个目标服务。
- 不做导入(把外部账单写进 tally),那是已延后的 batch import 方向。
- 不在服务端加导出接口,也不生成 PDF/Excel。

## Decisions

### D1 目标格式锁死 7 列,不加子分类列

目标网页只读 `日期,类型,分类,金额,货币,备注,账户` 七列,其余列被忽略。曾考虑额外输出"子分类"列以便用户日后参考,但该列不会进入导入结果,反而让用户以为导入后能保留层级,故不输出。

替代方案:输出 8 列并在交付说明里解释"子分类列会被忽略"。否掉的原因是预期会反复被追问"为什么导进去没有子分类"。

### D2 分类只写一级,不拼接

网页把"分类"当一级分类名做完全相等匹配。拼接成"餐饮-外卖"必然匹配失败,用户还得逐条修;只写"餐饮"则至少能匹配上,二级由用户导入后自己调整(用户已确认这是他要的做法)。取法因此是:有父分类取父分类名,否则取自身。

替代方案:导出时把二级分类名映射到网页已有的一级分类。否掉是因为这需要维护一份跨系统的映射表,网页改版或分类增减都会失真。

### D3 日期减一天,而不是改成日期格式

网页解析时写死 `add(1, "days")`,与输入格式无关。所以避开这个偏移的唯一办法是在写文件时减一天。时分秒保留,让导入后的时间与账本一致;月初交易落到上月最后一天是预期,不是 bug。

替代方案:写日期字符串时绕开它的解析分支(例如带时区标记)。未验证且依赖未公开的实现细节,不如直接减一天稳定。

### D4 账户固定写"默认",不用 tally 的来源名

网页按账户名完全匹配自己的账户列表,匹配不上显示 `-1`。用户指定统一写"默认"。把来源名写进去不会带来任何信息增益(来源本来就不属于目标系统的账户体系),只会制造待修的行。

### D5 金额写正数,货币写"人民币"

网页导入时取绝对值,并清空货币列。因此符号和币种在目标侧都不承载语义。若将来目标服务开始区分收支符号,这条要重新评估。

### D6 文件用脚本生成、utf-8-sig、升序、≤3000 笔

用脚本是为了让对账可复算,也避免长 `comment` 里的逗号/引号破坏结构。BOM 让 Excel 直接打开不乱码。升序让导入预览符合人的阅读顺序。单文件上限来自对导入页一次处理量的保守估计,超量按月拆分。

### D7 规则失效的检测方式:先小样

网页改版无法从 tally 侧感知。约定"拿不准先导一条测试",把检测成本压到最低,而不是在 skill 里维护一个网页版本号。

## Risks / Trade-offs

- **网页改版导致日期偏移或列语义变化** → 交付前的小样测试 + 交付说明里写清日期已提前一天,用户能第一时间发现错位。
- **分类名与网页侧不一致(用户改过名)** → 对账只保证"行数与金额",不能保证分类匹配;交付说明里提示导入预览要检查未匹配的分类。
- **超过 3000 笔时按月拆分,跨月边界的交易可能被用户误认为漏导** → 拆分文件名带月份,交付说明列出每个文件的范围与笔数。
- **`comment` 超过 60 字被网页截断** → skill 要求在回复里点明,不擅自截断 `comment`(那会破坏 comment 纪律)。

## Migration Plan

无数据迁移。既有 `plugin/skills/export/SKILL.md` 即为实现,本变更归档后只新增主 spec,不改运行中的行为。

## Open Questions

无。目标服务的其他导入页(若有)留到用户实际提出时再读其脚本,不在本次范围内猜测。
