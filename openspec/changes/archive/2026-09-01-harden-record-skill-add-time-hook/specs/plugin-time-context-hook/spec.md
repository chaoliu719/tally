## Purpose

在会话开始与每轮用户输入时,向 agent 的对话上下文注入当前日期、星期与本地时区,作为
agent 把「今天」「昨天」「上周五」这类相对时间表达解析为具体日期的可靠锚点,消除 agent
凭印象心算日期导致记账日期错误的问题。

## ADDED Requirements

### Requirement: 会话开始时注入当前时间上下文
插件 SHALL 提供一个在会话开始时运行的 hook,向 agent 的上下文注入当前日期、星期与
本地时区,取值 SHALL 来自运行时的系统时钟(等价于 `date` 命令的输出),而非任何缓存或
硬编码值。

#### Scenario: 新会话启动
- **WHEN** 一个新的 agent 会话开始
- **THEN** hook 输出包含当前日期(年-月-日)、星期几与本地时区(名称与 UTC 偏移)的一行上下文,供 agent 后续解析相对时间表达时作为锚点

### Requirement: 每轮用户输入刷新当前时间上下文
插件 SHALL 提供一个在每轮用户输入提交时运行的 hook,重新注入当前日期与时区,使跨越
自然日边界的长会话中 agent 始终持有正确的「今天」。

#### Scenario: 会话跨过午夜
- **WHEN** 一个会话持续到本地日期发生变化之后,用户提交新的输入
- **THEN** hook 注入的当前日期反映最新的本地日期,而不是会话开始时的日期

### Requirement: hook 仅注入上下文,不做拦截或判断
该 hook SHALL 只向上下文追加时间信息,不拦截、不阻断、不修改任何工具调用,也不做任何
语义判断;它不引入常驻后台进程,每次仅同步读取一次系统时钟即返回。

#### Scenario: hook 执行
- **WHEN** hook 被触发
- **THEN** 它读取一次系统时钟、输出时间上下文文本后立即结束,不改变工具调用的准许与否,也不产生后台驻留进程

### Requirement: 注入内容不假设服务端时区语义
hook 注入的时区信息 SHALL 明确标注为「用户本地时区」,供 agent 在缺少更明确信息时作为
默认假设;它不改变 tally MCP 协议中 `time` 字段为纯 Unix 秒数、无时区语义的事实。

#### Scenario: agent 使用注入的时区
- **WHEN** agent 依据 hook 注入的时区把用户的本地时间表达换算为 Unix 秒数
- **THEN** agent 把该时区当作默认假设(用户可在预览阶段纠正),而不将其理解为服务端存储或返回的时区
