导出 = 把账本里**已经存在**的交易原样搬进一个 CSV,交给别的工具导入。它不新增、不修改、
不删除 tally 里的任何数据,所以全程只用读类工具(`search_transactions` / `list_categories`
/ `list_sources` / `open_transaction_timeline` 的摘要)。

目前唯一的目标是"共享记账"的账单导入网页(`https://member.gongxiangjizhang.com/#/add-account`)。
下面的规则全部来自读它的前端脚本(`app.6dc585f9.js`,2026-10 读取),不是猜的;网页改版后
行为可能变,拿不准时先用单条测试文件验证,不要直接导整月。

## 1. 先划定范围、取全量

- 用户说"十月"就是 10-01 到 10-31;相对表达("上个月""最近 7 天")照 query skill 的时间
  纪律先用 `date` 算好再传。账本不确定先 `list_ledgers` 让用户选。
- `search_transactions` 每页有上限,用 `next_cursor` 翻到底,别只取第一页。
- 取完先用 `open_transaction_timeline` 同范围的摘要(笔数、支出合计)记下来,导出后对账用。

## 2. 列与取值(网页只认这 7 列)

表头固定,顺序固定:`日期,类型,分类,金额,货币,备注,账户`。

- **没有"子分类"列。** 网页只读上面 7 列,多出来的列(包括"子分类")会被直接忽略,
  加了也导不进去。
- **类型**:`支出` / `收入`,必须是这两个字。tally 的 `type` 是 `expense` 就写 `支出`。
  用户没明确要收入就只导支出;用户说过"收入不要"的,收入类交易(如利息收入)不导出,
  并在回复里说明有几笔被排除。
- **分类**:只写**一级分类**。网页把这一列当成"一级分类名"去和它自己那边的分类名做完全
  相等的匹配;写二级分类名会被当成一级、对不上。二级分类由用户导入后在网页里逐条自己改,
  这是用户定的做法,不要擅自再写成"一级-二级""一级/二级"之类的拼接格式——那样也一定
  匹配不上。取法:`list_categories(ledger_id)`,交易的 `category_id` 若 `parent_id` 不是
  `"0"` 就换成它的父分类名,否则就是自己;本身就是一级且没有子分类的(如"其他")原样写。
- **金额**:正数、原样(如 `136.43`、`62.00`)。网页导入时会取绝对值。
- **货币**:写 `人民币`。网页会把这一列清空,写什么都不影响。
- **备注**:原样写交易的 `comment`,不要改写、不要补解释。网页预览里的备注输入框限长 60
  字,更长的在预览里可能显示被截,有超长的交易要在回复里提一句。
- **账户**:统一写 `默认`(用户指定)。网页按名字完全匹配它自己的账户列表,匹配不上会显示
  `-1`。不要把 tally 的来源名(如"信用卡(尾号3473)")写进来。

## 3. 日期:整体提前一天

网页在解析日期时写死了加一天(源码 `add(1,"days")`),不管写成 `2026-10-01`、
`2026/10/01` 还是带时分秒,导入后都会变成 10-02。所以**每个日期都要先减一天再写**:
tally 里 `2026-10-01 08:42:00` 写成 `2026-09-30 08:42:00`,导入后正好显示 10-01。
时分秒保留,格式用 `YYYY-MM-DD HH:MM:SS`。月初的交易会落到上个月最后一天,这是预期行为,
不是错。

## 4. 生成文件

- 用脚本生成,不要手拼文本:Python `csv` 模块,`encoding="utf-8-sig"`(带 BOM,Excel 直接
  打开不乱码),`newline=""`。
- 按时间升序排。一次不超过 3000 笔,超了就按月拆。
- 文件名带范围和用途,如 `2026年10月账单_导入版_一级分类.csv`。

## 5. 对账再交付

导出完必须核对两件事,不要只信脚本没报错:

- 行数 = 第 1 步摘要里的笔数(减去被排除的收入笔数,若有)。
- 金额合计 = 摘要里的支出合计。

不一致就先查原因,别交付。交付时说清:共几笔、合计多少、有没有被排除的笔、日期已经提前
一天(否则用户看到文件里的日期和账本差一天会以为导错了)。

用户想先试水时,另给一个只含第一笔的单条 CSV。

## 6. 纪律

- **不要未经要求改任何值。** 分类名、备注、来源、日期的处理方式只有上面写的这几条;
  想"顺手对齐"另一个系统的命名之前先问。(做过一次未经确认的分类名替换,用户明确不满意。)
- 用户要换格式(比如要二级分类、要别的网页的模板)时,先确认目标工具认什么列、什么
  取值,必要时像上面一样读它的前端代码或做小样测试,再出文件。
