查账就是"把账本里已经存在的交易原样取出来给用户看"——单笔或一段时间的清单。
它不做跨时段汇总、环比、类别占比那些(那是 `analysis` 的事),也不改动任何数据
(那是 `record` 的事)。这个 skill 只管一件事:怎么把查询发对、怎么把结果读对、
怎么把时间显示对。

## 先确认账本

用户有多个账本时,`search_transactions` / `get_financial_summary` 都要 `ledger_id`。
不确定查哪个账本先 `list_ledgers` 摆给用户选,不要默认第一个。单账本可直接用。

## 两类查询

**查某一笔 / 某商户的历史。** 用户问"上次在 XX 花了多少""XX 那笔备注写的啥":
用 `search_transactions(ledger_id, keyword=<商户名/关键词>)` 按 `comment` 子串命中。
- `keyword` 大小写不敏感、**不支持通配符**——`%` `_` 会被当字面字符匹配,别为了"搜宽
  一点"往里加,加了反而可能搜不到。
- 想搜宽就换更短、更核心的词;想搜窄就多给几个字。命中多笔时按时间摆出来让用户认。
- 要看某一笔的完整字段(比如确认 `comment` 原文、`source_id`/`category_id`),用
  `get_transaction(id)` 取全量,不要只依赖搜索结果里的摘要。

**查一段时间的清单。** 用户说"这个月的账""昨天买了啥""上周的开销明细":用
`search_transactions` 传时间窗口(`start_time`/`end_time`),不传 `keyword` 或只传
一个宽泛词。结果按时间排好逐笔列出。**这是"列明细",不是"算总账"**——用户要的是
"花了多少合计"就转 `analysis`。

## 时间换算:查询前算一次,查询后直接展示,全程不许心算

`time` / `start_time` / `end_time` 都是 `YYYY-MM-DD HH:MM:SS` 格式的本地日期时间
字符串,不带任何时区标记——协议里没有时区概念,服务端不校验、不提醒,原样存、原样还。

**第 0 步:确认当前日期。** Claude Code / claude.ai 的系统提示词本身会把当前日期注入
对话上下文,直接用它作锚点;没看到时先跑一次 `date` 取当前时刻。后面所有"本月/昨天/
上周"的边界都按这个日期算。

**查询前 —— 把相对表达算成 `YYYY-MM-DD HH:MM:SS` 窗口再传:**
- 昨天:`date -v-1d -v0H -v0M -v0S +"%Y-%m-%d %H:%M:%S"`(起) 到
  `date -v0H -v0M -v0S +"%Y-%m-%d %H:%M:%S"`(今天 0 点,止)
- 本月至今:`date -v1d -v0H -v0M -v0S +"%Y-%m-%d %H:%M:%S"` 到
  `date +"%Y-%m-%d %H:%M:%S"`
- "最近 7 天":`date -v-7d +"%Y-%m-%d %H:%M:%S"` 到 `date +"%Y-%m-%d %H:%M:%S"`
- Linux 用 `date -d "..." +"%Y-%m-%d %H:%M:%S"`

直接取命令输出塞进 `start_time`/`end_time`,不要凭感觉写数字。边界差一天,跨天的
交易就漏了或多了。

**查询后 —— 直接展示返回的日期时间字符串,不需要再换算:**
`search_transactions`/`get_transaction` 返回的 `time` 已经是人类可读的
`YYYY-MM-DD HH:MM:SS`,直接念给用户(可以补充星期等易读信息),不用再跑 `date` 反查,
也**绝对不要**自己脑补一个时区偏移去心算——这个字符串本身就是记账当时的墙上钟时刻。

## 三条容易读错的字段语义

服务端不做任何校验或提醒,读错了不报错,只会把清单念错:

- **`amount` 的符号 / 收支方向按 tally 现有约定理解**,不要看到数字就默认是支出。
  拿不准就连带把分类、`comment` 一起摆出来让用户判断。
- **多币种不换算。** 一段时间的清单里若有多种币种,分币种分别列,不要按汇率合并成
  一个数——那是自作主张,且汇率你也没有。
- **`comment` 是原文,结构化字段是解释。** 用户问"这笔是什么",先念 `comment`
  原文,再补分类/来源;不要只把分类名念给用户当答案。

## 不在这个 skill 范围内

- 汇总、环比、类别占比、多月趋势 → `analysis`
- 记一笔 / 改一笔 / 拆多笔 → `record`
- 拆分或合并分类 → `optimize`
- 图表 / 可视化 → 按项目现有决定,暂不做
